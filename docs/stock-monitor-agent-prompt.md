# Stock Monitor Agent — Claude Code Prompt

Build a Node.js stock monitoring agent that runs as a daily digest system.

## Overview
Create a production-ready Node.js application that monitors a configurable
list of stock tickers, uses the Anthropic Claude API with web search to
research each ticker daily, and emails a formatted digest report.

## Project Structure
```
stock-monitor/
├── .env                    # config (never committed)
├── .env.example            # template for config
├── package.json
├── src/
│   ├── index.js            # entry point / orchestrator
│   ├── agent.js            # Claude API + web search logic
│   ├── mailer.js           # email delivery
│   ├── scheduler.js        # cron scheduling
│   └── formatter.js        # digest formatting (text + HTML)
└── README.md
```

## .env Configuration
```
ANTHROPIC_API_KEY=          # Claude API key
CLAUDE_MODEL=claude-sonnet-4-6   # model to use (optional, defaults to claude-sonnet-4-6)
EMAIL_TO=                   # recipient email address
EMAIL_FROM=                 # sender address
SMTP_HOST=                  # SMTP server (e.g. smtp.gmail.com)
SMTP_PORT=587
SMTP_USER=                  # SMTP username
SMTP_PASS=                  # SMTP password or app password
CRON_SCHEDULE=0 7 * * 1-5  # weekdays at 7am (configurable)
TICKERS=CEG,ETN,COHR,VST,TLN,GEV,VRT  # comma-separated watchlist
TICKER_DELAY_MS=2000        # delay between ticker API calls in milliseconds (optional, defaults to 2000)
```

## Agent Logic (agent.js)
- Use the Anthropic Node.js SDK (`@anthropic-ai/sdk`)
- Read model from `CLAUDE_MODEL` env var, default to `claude-sonnet-4-6`
- Enable the `web_search_20250305` tool so Claude can pull live data
- Read delay from `TICKER_DELAY_MS` env var, default to `2000` if not set:
  ```js
  const delay = parseInt(process.env.TICKER_DELAY_MS ?? '2000', 10);
  ```
- For each ticker, run a single API call with this research prompt:

```
Research stock ticker {TICKER} for today {DATE}. Use web search to find:
1. Current stock price and today's price movement (% change)
2. Latest analyst ratings and price target changes (last 7 days)
3. Recent news or catalysts (last 48 hours)
4. Key risk factors or headwinds mentioned in recent coverage
5. Overall sentiment: Bullish / Neutral / Bearish with a 1-2 sentence
   rationale

Be concise. Format your response as JSON with these exact keys:
ticker, price, change_pct, sentiment, analyst_targets, news_summary,
risks, one_liner
```

- Parse the JSON response from Claude
- Handle errors per ticker gracefully (don't fail the whole batch)
- Add the configurable delay between ticker API calls to avoid rate limits
- Log progress to console with timestamps

## Email Formatting (formatter.js + mailer.js)
- Use `nodemailer` for SMTP delivery
- Send both plain text and HTML versions (multipart)
- HTML digest layout:
  - Header: `📈 Daily Stock Digest — {DATE}`
  - One card per ticker showing:
    - Ticker symbol (large, bold) + company name
    - Price + % change (green if positive, red if negative)
    - Sentiment badge (color-coded: green/yellow/red)
    - One-liner summary
    - Analyst targets section
    - News summary (2-3 bullets)
    - Risks (1-2 bullets)
  - Footer: `Generated by Claude {CLAUDE_MODEL} with web search`
- Plain text fallback with same info, simple formatting

## Scheduler (scheduler.js)
- Use `node-cron` package
- Read schedule from `CRON_SCHEDULE` env var
- Default: weekdays at 7:00 AM local time (`0 7 * * 1-5`)
- Log next scheduled run on startup
- Support a `--run-now` CLI flag to trigger immediately (for testing)

## Entry Point (index.js)
- Load `dotenv` at the top
- Validate all **required** env vars on startup; exit with a clear error
  message if any are missing:
  - Required: `ANTHROPIC_API_KEY`, `EMAIL_TO`, `EMAIL_FROM`, `SMTP_HOST`,
    `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `TICKERS`
  - Optional (use defaults): `CLAUDE_MODEL`, `CRON_SCHEDULE`, `TICKER_DELAY_MS`
- Check for `--run-now` flag: if present, run immediately and exit
- Otherwise start the scheduler and keep the process alive
- Graceful shutdown on `SIGINT` / `SIGTERM`

## Error Handling Requirements
- If Claude API call fails for a ticker: log error, include a
  "data unavailable" placeholder card in the digest
- If email delivery fails: log full error with SMTP details
- If web search returns no results: Claude should note
  "limited data available" in the summary
- Never crash the process on a single ticker failure

## Code Style
- ES modules (`import`/`export`), not CommonJS
- `async`/`await` throughout, no callbacks
- Clear console logging with emoji prefixes for readability:
  ```
  🔍 Researching TICKER...
  ✅ TICKER complete
  📧 Sending digest...
  ✅ Digest sent to EMAIL
  ❌ Error: [message]
  ```
- No TypeScript, plain Node.js only
